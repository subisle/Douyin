# 微信机器人轻量 AI Agent 优化计划

> 状态：待实施
> 日期：2026-07-21
> 范围：在现有 Electron 微信 iLink 机器人上补齐双团日报、字段设置、自动文件导入和数据型 AI Agent。
> 核心约束：复用现有数据库、报表和媒体能力，首版保持小型、可测试、可随时关闭。

## 1. 目标

首版交付以下能力：

1. 用户发送 `每日报告` 时，机器人取音浪数据的最新已有日期，依次发送男团和女团报告图片。
2. 报告默认只隐藏“有效时长”，其他字段正常展示。
3. 用户发送 `设置字段` 后，机器人返回编号菜单；用户只需回复数字即可设置后续报告不展示的字段。
4. 用户直接发送音浪或时长 CSV 文件时，机器人自动完成下载、解密、识别、解析、主播匹配、去重导入和结果回执。
5. 普通自然语言进入轻量 AI Agent。Agent 只通过受控技能读取已有数据，并可返回文字、报告图片或 CSV 文件。
6. 支持“某主播音浪怎么样”“两位主播谁更好”“导出 18 号男团报告图”“发最新音浪文件”等对话。
7. iLink 登录、长轮询、`context_token`、媒体 AES 加解密和 CDN 上传继续使用现有实现。

## 2. 首版边界

为控制项目体积，首版采用以下约束：

- 不引入完整 LangChain/LangGraph 运行依赖；参考其 `agent -> tool -> observation -> agent` 循环、工具 schema 和 thread memory 设计，自建一个小型有界执行器。
- 最多新增两个运行时模块：`weixin-bot-agent.js` 和 `weixin-bot-skills.js`。
- 不新增数据库表；数据查询继续走 `electron/db.js`，非敏感偏好写入现有微信机器人本地存储。
- 不加入向量库、RAG、多 Agent、网页搜索、Shell、任意文件系统访问或后台定时推送。
- 首版数据附件支持 CSV；图片作为机器人输出。图片理解、OCR、Excel 工作簿和语音处理留作后续独立增量。
- 确定性命令优先于 AI，AI 服务停用或调用报错时，现有命令仍可使用。

当技能数量超过约 12 个、出现复杂分支/人工审批或需要持久化工作流时，再评估直接换成 LangChain `createAgent` 或 LangGraph；技能接口保持兼容，避免重写业务逻辑。

## 3. 用户行为规范

### 3.1 路由优先级

每条入站消息严格按以下顺序处理：

```text
文件附件
  -> 等待数字回复的字段设置会话
  -> 明确命令
  -> AI Agent 自然语言
  -> 现有固定自动回复
```

这样可保证导入和报表等关键操作不依赖模型判断，也避免数字回复被模型误解。

### 3.2 命令表

| 输入示例 | 目标行为 |
| --- | --- |
| `每日报告` | 取最新音浪日期，发送男团和女团两张报告图 |
| `每日报告 18号` | 指定日期，发送男团和女团两张报告图 |
| `男团每日报告` | 只发送男团；未写日期时取最新音浪日期 |
| `女团每日报告` | 只发送女团；未写日期时取最新音浪日期 |
| `18号音浪` | 保留现有习惯，默认发送男团报告图 |
| `主播名时长` | 查询最近时长快照中的累计直播时长 |
| `主播名多少日音浪` | 查询当月有音浪天数、未播天数和累计音浪 |
| `主播名18号音浪` | 查询主播指定日期的日音浪和当月累计音浪 |
| `设置字段` | 返回编号菜单并等待数字回复 |
| `音浪文件 18号` | 发送指定日期音浪 CSV；未写日期时取最新音浪日期 |
| `帮助` | 返回精简命令列表和字段设置入口 |

### 3.3 `每日报告` 的精确定义

- “最新已有日期”只看 `wave_snapshots.import_date` 的最大值，不使用可能只有时长数据的日期。
- 男团和女团必须使用同一个日期，发送顺序固定为男团、女团。
- 先发送一条总回执，再发送两张图片，减少重复文字消息。
- 某一团没有主播数据或单张图生成失败时，另一团继续发送，并单独返回该团的错误摘要。
- 显式指定日期但该日没有音浪快照时，直接说明该日期无数据，不自动跳到其他日期。
- `男团每日报告`、`女团每日报告` 和 `18号音浪` 保留单团输出，兼容现有用法。

### 3.4 报告字段设置

“主播姓名”固定保留，避免报告失去对象。其他字段编号如下：

| 编号 | 字段 | 默认状态 |
| --- | --- | --- |
| 1 | 排名 | 展示 |
| 2 | 本月未播天数 | 展示 |
| 3 | 当日音浪 | 展示 |
| 4 | 当月累计总音浪 | 展示 |
| 5 | 有效时长 | 隐藏 |
| 6 | 师傅 | 展示 |
| 7 | 等级 | 展示 |

交互规则：

```text
用户：设置字段
机器人：回复不想展示的字段编号，例如“2 5”。当前隐藏：5 有效时长。
用户：2 5
机器人：已设置，后续报告隐藏：本月未播天数、有效时长。
```

- 数字回复采用“替换隐藏列表”语义，不做隐式累加，结果更容易预测。
- 支持空格、逗号和中文顿号，例如 `2 5`、`2,5`、`2、5`。
- 回复 `0` 表示全部展示；回复 `默认` 恢复只隐藏有效时长；回复 `取消` 退出设置。
- 等待数字回复的状态有效期为 5 分钟，仅匹配发起设置的同一会话参与者。
- 私聊按 `fromUserId` 隔离；群聊按 `groupId + fromUserId` 隔离，避免其他群成员的数字消息修改设置。
- 每个参与者保存一份字段偏好，最多保留最近 50 份；超出时淘汰最久未使用项。
- 字段偏好持久化，Agent 对话正文不持久化。

## 4. 总体架构

```text
iLink getupdates
  -> WeixinBotService（鉴权、游标、context_token、收发队列）
     -> Attachment Import（确定性文件路径）
     -> Command Router（确定性命令、字段设置）
     -> Lightweight Agent（自然语言、有界工具循环）
        -> Skill Registry（JSON Schema + 参数校验 + 权限）
           -> db.js / report renderer / CSV exporter
     -> Reply Dispatcher（text / image / file）
        -> iLink getuploadurl + AES-128-ECB CDN upload + sendmessage
```

关键原则：

- `weixin-bot.js` 只负责 iLink 传输、上下文和调度，不放业务查询规则。
- 命令和 Agent 技能共用同一批业务函数，避免日报日期、主播匹配和统计口径出现两套实现。
- 模型只看到工具返回的精简 JSON，不直接访问数据库连接、文件路径或媒体 Buffer。
- 图片和文件以 `artifact` 在进程内传递；发给模型的 observation 只包含文件名、日期、条数等元数据。
- 每个参与者串行处理消息，防止连续消息交叉使用旧 `context_token` 或覆盖会话状态。

## 6. Agent 设计

### 6.1 Provider 配置

首版只实现 OpenAI-compatible Chat Completions + tools：

- `agentEnabled`：默认关闭，配置完整后由用户开启。
- `baseUrl`：支持 HTTPS；本机模型可使用 loopback HTTP。
- `model`：用户填写服务端已有模型名。
- `apiKey`：仅主进程持有，使用 Electron `safeStorage` 加密后落盘。
- `hasApiKey`：渲染进程只读取布尔值，设置接口不回传明文密钥。
- `timeoutMs`：默认 45 秒。
- `maxToolRounds`：默认 4，硬上限 6。

请求日志只记录 provider、模型、耗时、工具名和结果状态；Authorization、完整提示词、数据库明细和媒体内容不写日志。

### 6.2 有界工具循环

```text
1. 组合 system prompt + 最近会话 + 当前消息
2. 调用模型
3. 没有 tool_calls -> 输出文字并结束
4. 校验工具名、参数、当前权限和附件上下文
5. 执行工具，收集结构化 observation / artifact
6. 回到步骤 2，最多 4 个工具轮次
7. 达到轮次或总超时 -> 返回已获得的事实摘要和任务状态
```

限制：

- 同一轮最多执行 3 个只读工具，总工具调用数最多 8 次。
- 未注册工具、非法参数和模型伪造的附件 ID 都作为结构化工具错误返回，不执行副作用。
- 首版只有文件入站路径可触发导入；普通文本对话不开放任意写数据库工具。
- 最终文字控制在约 1500 个中文字符；超过 iLink 单条限制时按段落切成不超过 3500 字的多条消息。
- provider 错误只影响本次自然语言消息，命令路由和文件导入继续运行。

### 6.3 短期对话状态

参考 LangChain `thread_id`，以私聊用户或 `groupId + fromUserId` 作为 thread key：

- 保存最近 8 轮 user/assistant 摘要，总字符数最多 12,000。
- 保存 `lastAnchor`、`lastDate` 和上一次工具结果摘要，支持“那他 18 号呢”“导出成图片”等追问。
- 30 分钟无消息后过期；应用退出后清空，不持久化聊天正文。
- `清空对话` 只清除当前 thread 的 Agent 记忆，不清除字段偏好和 iLink 登录。
- 最多保留 100 个活跃 thread，按最近使用时间淘汰。

### 6.4 数据约束

System prompt 固定要求：

- 所有业务数字来自工具结果，不根据常识补数。
- 回答必须标注数据截止日期；不同指标日期不一致时分别标注。
- 主播名匹配不唯一时列出候选并让用户补充主播 ID/抖音号。
- 空数据返回“日期 + 查询范围 + 0 条结果”，不把 0 当成真实表现。
- 评价必须同时给出数值依据、同队样本量和使用的时间窗口。

## 7. 首批技能

| 技能名 | 用途 | 主要输出 |
| --- | --- | --- |
| `get_anchor_wave_profile` | 回答“某主播音浪怎么样” | 截止日、当日/当月音浪、同队排名、直播天数、未播天数、近期趋势 |
| `compare_anchor_wave` | 比较 2-5 位主播 | 同一截止日和同一性别样本下的指标表与差值 |
| `get_anchor_duration` | 查询主播时长 | 最近快照日期、累计分钟和格式化时长 |
| `get_daily_report_data` | 获取男团/女团日报数据 | 日期、行数、汇总和可见字段 |
| `export_daily_report_image` | 生成并发送日报图 | artifact：PNG Buffer、文件名、日期、性别 |
| `export_wave_file` | 生成并发送音浪数据文件 | artifact：UTF-8 BOM CSV、文件名、行数 |
| `import_attached_data` | 解析当前消息携带的数据文件 | 仅附件路由可用；导入统计和未匹配清单 |

默认规则：

- 自然语言只说“发报告图片”但未指定性别时，默认男团。
- 明确说“每日报告”时仍走确定性双团命令，不交给模型猜测。
- 未写日期的查询/导出使用对应数据类型的最新已有日期。

### 7.1 “音浪怎么样”的确定性评测

技能返回事实和标签，模型只负责组织语言：

- **位置**：按同团当月累计音浪计算排名和百分位。
- **趋势**：最近 3 个有数据日均值与之前 3 个有数据日均值比较；上涨 `>= 15%`、回落 `<= -15%`，其余为平稳。
- **活跃度**：本月达到现有开播音浪阈值的天数 / 截止日已过天数。
- **稳定性**：最近 7 个有数据日的变异程度；样本少于 3 天时标记样本不足。
- **结论依据**：始终附截止日期、样本天数、同团人数和关键数值。

阈值集中放在技能模块常量中并写单元测试，不散落在 prompt 里。

## 8. 图片和文件输出

### 8.1 报告图片

- 继续使用 `sharp` 在 Electron 主进程中渲染，不依赖浏览器当前页面。
- `renderDailyReportPng(report, { visibleFields, title })` 根据字段动态计算列宽和图片高度。
- 默认字段为：排名、主播姓名、本月未播天数、当日音浪、累计总音浪、师傅、等级。
- 只有用户通过字段设置明确展示时长，才渲染“有效时长”。
- 文件名统一为 `YYYY-MM-DD_男团_每日报告.png` 或 `YYYY-MM-DD_女团_每日报告.png`。

### 8.2 CSV 文件

- 导出统一使用 UTF-8 BOM，保证微信下载后用常见表格软件直接打开中文。
- 文件名统一为 `YYYY-MM-DD_音浪数据.csv`。
- Buffer 不进入模型上下文；工具只返回文件元数据，Reply Dispatcher 负责 iLink 上传。
- 每个 artifact 独立发送并记录成功/失败，单个文件失败不丢失已经生成的文字答复。

## 9. 自动文件导入

### 9.1 流程

```text
收到 type=4 文件
  -> 根据 iLink media 描述下载
  -> AES-128-ECB 解密
  -> 校验大小、扩展名和 CSV 表头
  -> UTF-8 BOM / UTF-8 / GB18030 解码
  -> 根据表头识别音浪或时长
  -> 解析日期
  -> 精确匹配主播账号/别名/唯一姓名
  -> 文件哈希 + 规范化数据哈希去重
  -> 调用现有 importWaveSnapshots / importDurationSnapshots
  -> 回复导入结果；有未匹配行时附送 rejected CSV
```

### 9.2 识别规则

- 类型优先级：表头字段 > 消息附言 > 文件名；文件名只做辅助判断。
- 日期优先级：消息附言 > 文件名 > CSV 日期列 > 本地“昨日”。
- 回执必须说明最终导入日期及日期来源，避免自动推断不可见。
- 主播匹配顺序：`anchorId` > 抖音号 > alias ID > 唯一的规范化姓名。
- 模糊姓名只用于给出候选，不直接写库。
- 同一文件中的重复主播保留最后一条，并在回执中计数。
- 继续使用现有文件 MD5 和规范化数据 SHA-256 防止重复导入。
- 单文件导入上限建议为 20 MB / 50,000 行，超限直接返回文件大小和限制。

### 9.3 导入回执

成功示例：

```text
已导入 2026-07-18 音浪数据（日期来自文件名）：
有效 36 条，未匹配 2 条，重复 1 条，非法 0 条。
未匹配明细已附在 2026-07-18_未匹配.csv。
```

## 10. 分期实施

### 阶段 A：日报与字段会话

- 调整 `每日报告` 为同日男团 + 女团输出。
- 报告渲染器支持动态字段，默认隐藏有效时长。
- 加入 `设置字段` 数字会话、持久化和帮助文案。
- 补命令解析、会话隔离和图片字段测试。

验收后单独提交，确保 AI 尚未接入时核心需求已经可用。

### 阶段 B：自动文件导入加固

- 将当前 CSV 导入补齐表头识别、日期来源、大小限制和 rejected CSV。
- 保留现有媒体解密、主播匹配和重复导入保护。
- 覆盖 UTF-8 BOM、UTF-8、GB18030、重复文件、未知主播和错误表头测试。

### 阶段 C：轻量 Agent 与技能

- 新增 provider、tool loop、短期 thread state 和技能注册表。
- 先接只读查询技能，再接图片/文件 artifact 技能。
- 在微信机器人页面加入 AI 设置；API Key 全程留在主进程。
- 使用 mock OpenAI-compatible 响应测试单工具、多工具、非法工具、超时和轮次上限。

### 阶段 D：联调与收尾

- 用 mock iLink 验证文字、双图、CSV、附件导入和 `context_token` 透传。
- 用真实已连接微信做一次受控冒烟测试，记录接口尺寸和频率表现。
- 执行测试、lint、生产构建；更新帮助文案和设置状态展示。

## 11. 测试矩阵

### 11.1 单元测试

- `每日报告` 无日期时只查询一次最新音浪日期，并用该日期请求男女两团。
- 双团发送顺序固定；一团失败不阻塞另一团。
- 默认报告 SVG/PNG 中没有“有效时长”，有“师傅”；设置 `0` 后包含有效时长。
- `设置字段 -> 2 5`、`0`、`默认`、`取消`、超时、跨会话数字均符合约定。
- 日期解析覆盖今日、昨日、18 号、7 月 18 日和完整 ISO 日期。
- 文件导入覆盖编码、表头、日期来源、alias 匹配、重复、非法值和未匹配导出。
- Agent 覆盖无工具、单工具、多工具、未知工具、非法参数、最大轮次和 provider 超时。
- artifact 测试确认 Buffer 不进入模型消息，最终通过 `replyImage` / `replyFile` 发送。
- 所有业务回答包含 `asOfDate`；空结果不会生成评价标签。

### 11.2 集成测试

- mock `getupdates` 入站消息携带的 `context_token` 原样用于每一条文字、图片和文件回复。
- 同一参与者的连续消息串行执行，不同参与者可独立处理。
- iLink 图片/文件上传继续校验 AES key、密文长度、MD5 和下载参数。

## 12. 验收场景

以下场景全部通过才视为首版完成：

1. 数据库最新音浪日期为 `2026-07-18` 时，发送 `每日报告`，收到同日期男团、女团两张图片，图片均不含有效时长。
2. 发送 `设置字段` 后回复 `2 5`，下一次两团报告同时隐藏未播天数和有效时长；重启应用后设置仍生效。
3. 发送 `默认` 恢复只隐藏有效时长；发送 `0` 后报告展示全部可选字段。
4. 发送 `小张音浪怎么样`，答复包含截止日期、当日/累计音浪、同团排名、近期趋势和样本数，所有数字可由数据库结果复算。
5. 发送 `小张和小李最近谁的音浪更好`，两人使用同一截止日期和同一时间窗口比较。
6. 发送 `导出 18 号女团报告图片`，收到女团 PNG；只说 `发报告图片` 时收到男团 PNG。
7. 发送 `发最新音浪文件`，收到最新音浪日期的 UTF-8 BOM CSV。
8. 直接发送合法音浪 CSV，机器人自动导入并返回日期来源和统计；存在未匹配主播时同时收到 rejected CSV。
9. AI provider 关闭或本次调用报错时，`每日报告`、主播查询、字段设置和文件导入仍正常工作。

## 13. 风险与回滚

| 风险 | 控制措施 |
| --- | --- |
| iLink API 版本或限频未公开 | 保持协议封装集中；媒体逐条发送；失败独立重试；记录 endpoint 和错误码 |
| 模型工具调用格式不一致 | provider 适配层统一响应；严格 schema 校验；未知工具不执行 |
| AI 编造业务数字 | 数据只经技能读取；工具结果带日期/样本；prompt 和测试共同约束 |
| 同名主播导错数据 | 写入只接受账号精确匹配或唯一姓名；歧义行进入 rejected CSV |
| 长对话成本和延迟增长 | 8 轮/12,000 字上限、30 分钟 TTL、4 个工具轮次和 45 秒总超时 |
| 新功能影响现有机器人 | `agentEnabled` 功能开关；确定性命令优先；各阶段独立提交 |
| 本地设置升级 | 存储结构增加版本号和默认迁移；字段缺失时恢复安全默认值 |

最快回滚方式是关闭 `agentEnabled`，保留确定性命令与文件导入；日报字段变更和 Agent 分阶段提交，可按提交粒度回退。
